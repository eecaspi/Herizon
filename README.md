# HERizon | שיחות היכרות: מדריך הפעלה

המערכת מורכבת מ:

| חלק | קובץ | מה הוא עושה |
|---|---|---|
| האתר (מועמדות + ניהול) | `site/index.html` + `site/config.js` | קובץ סטטי אחד, בלי שרת ובלי build |
| מסד נתונים | `supabase/schema.sql` | טבלאות, הרשאות, מניעת כפילויות |
| מיילים | `supabase/functions/send-email/index.ts` | אישור, תזכורת והתראה למנהלות |

עלות: Supabase (חינם), אירוח האתר (חינם), Resend לשליחת מיילים (חינם עד 3,000 מיילים בחודש).

**כל עוד `config.js` ריק, האתר עובד במצב הדגמה** (הנתונים נשמרים בדפדפן בלבד ולא נשלחים מיילים). כך אפשר לשחק איתו לפני החיבור.

---

## שלב 1: מסד נתונים (כ-10 דקות)

1. נכנסים ל-https://supabase.com, פותחים חשבון ויוצרים Project (מומלץ אזור Frankfurt או London).
2. **SQL Editor → New query**: מדביקים את כל התוכן של `supabase/schema.sql` ולוחצים Run.
3. **Authentication → Users → Add user → Create new user**: יוצרים משתמשת לכל מנהלת (מייל + סיסמה), ומסמנים **Auto Confirm User**.
4. חוזרים ל-SQL Editor ומריצים (עם המיילים האמיתיים, באותיות קטנות):
   ```sql
   insert into public.admins (email) values ('esti@example.com'), ('arbel@example.com');
   ```
   רק מי שמופיעה בטבלה הזו מקבלת גישה לניהול, גם אם יש לה משתמשת.
5. **Authentication → Sign In / Providers → Email**: כדאי לכבות **Allow new users to sign up**, כדי שאף אחת לא תוכל ליצור משתמשת בעצמה.
6. **Project Settings → API**: מעתיקים את `Project URL` ואת `anon public key` ל-`site/config.js`.

## שלב 2: העלאת האתר (כ-5 דקות)

האפשרות הפשוטה ביותר: https://app.netlify.com/drop, גוררים את התיקייה `site` לדף, ומקבלים לינק (אפשר לשנות שם ב-Site settings). חלופות חינמיות: Cloudflare Pages או GitHub Pages.

- לינק למועמדות: `https://השם-שלך.netlify.app/`
- כניסת צוות: `https://השם-שלך.netlify.app/#admin`

## שלב 3: מיילים (כ-15 דקות)

עד שלב זה המערכת קובעת ראיונות בפועל, אבל **לא שולחת מיילים**. במסך האישור למועמדת תופיע הודעה ש"לא הצלחנו לשלוח מייל אישור", ולא תופיע הודעה שמייל נשלח. זה מכוון.

1. נרשמים ל-https://resend.com. **חשוב:** בלי אימות דומיין, Resend שולח רק לכתובת של בעלת החשבון. כדי לשלוח למועמדות צריך לאמת דומיין (Domains → Add Domain, מוסיפים רשומות DNS אצל חברת הדומיין). לדומיין של DDos Women, או כל דומיין אחר שיש לכן, זה עניין של כמה דקות.
2. יוצרים API Key.
3. מתקינות את Supabase CLI ומריצות מתוך תיקיית הפרויקט:
   ```bash
   supabase login
   supabase link --project-ref <מזהה-הפרויקט>
   supabase secrets set RESEND_API_KEY=re_xxx FROM_EMAIL="HERizon <hello@your-domain.com>" SITE_URL=https://השם-שלך.netlify.app
   supabase functions deploy send-email --no-verify-jwt
   ```
4. באתר: **ניהול → הגדרות**: ממלאות "מייל להתראה על ראיון חדש" (ואת קישור ה-Meet).

מה נשלח:
- **אישור למועמדת** מיד אחרי קביעה, עם התאריך והשעה, קישור ל-Meet, ולינק אישי לשינוי/ביטול. למייל מצורף **זימון יומן אמיתי (‎.ics‎)** לשעה שנבחרה: ב-Gmail וב-Outlook אפשר להוסיף אותו ליומן בלחיצה, והוא כולל תזכורת 15 דקות לפני.
- **שליחת זימון מהניהול**: כפתור "שליחת זימון" בשורת הראיון שולח (או שולח מחדש) את הזימון למועמדת. אחרי "שינוי מועד" אפשר ללחוץ עליו, והזימון החדש מעדכן את האירוע הקיים ביומן שלה ולא יוצר כפילות.
- **התראה למנהלת** לכתובת שהוגדרה בהגדרות.
- **תזכורת** (גם היא עם זימון מצורף): כפתור "שליחת תזכורת" בשורת הראיון (ידני בשלב זה). אם תרצו תזכורת אוטומטית יום לפני, זו תוספת קטנה (Scheduled function).

## Google Meet

כרגע: **קישור קבוע אחד** שמוגדר בהגדרות ומופיע בכל אישור ותזכורת. הדרך הפשוטה ליצור אותו: ב-Google Calendar יוצרות אירוע, מוסיפות "Google Meet video conferencing" ומעתיקות את הקישור (או מקישור `meet.google.com/new`). מכיוון שהשיחות עוקבות זו אחר זו, קישור אחד מספיק.

יצירה **אוטומטית** של קישור נפרד לכל ראיון דורשת חיבור ל-Google Calendar API (פרויקט ב-Google Cloud, הפעלת Calendar API, והרשאה של חשבון Google שבו ייווצרו האירועים). אפשר להוסיף את זה בהמשך בתוך אותה Edge Function. כדאי להתחיל בקישור הקבוע.

## בדיקה לפני שליחה למועמדות

1. נכנסות ל-`#admin`, מגדירות זמינות (למשל יום ראשון 20:00-22:00).
2. פותחות את לינק המועמדות בחלון גלישה פרטית ומתאמות ראיון עם מייל אמיתי שלכן.
3. מוודאות: המשבצת נעלמה מהרשימה, השורה מופיעה בניהול, המייל הגיע.
4. פותחות את הלינק משני טלפונים ובוחרות את אותה שעה. רק אחת תצליח, והשנייה תקבל הודעה ידידותית.

## אבטחה: מה חשוב לדעת

- מועמדות לא מתחברות ולא רואות פרטים של מועמדות אחרות: הן מקבלות רק רשימת שעות פנויות, ללא שמות.
- הטבלאות סגורות לגישה ציבורית. כל הפעולות של מועמדות עוברות דרך פונקציות מוגבלות במסד הנתונים.
- ניהול מוגן בהתחברות וברשימת `admins`.
- הנתונים נשמרים ב-Supabase עם הצפנה בהעברה ובאחסון.
- הערות פנימיות נשמרות בטבלה שרק מנהלות מורשות לקרוא.
- הלינק האישי לשינוי/ביטול מכיל מזהה אקראי ארוך, ומועמדת שמכירה אותו יכולה לשנות או לבטל רק את הראיון שלה.
- מניעת ספאם בסיסית: מועמדת עם אימייל שכבר יש לו ראיון עתידי לא יכולה לקבוע נוסף, ויש שדה מלכודת נסתר לבוטים. אם יתחילו לקבל הרשמות זבל, אפשר להוסיף Cloudflare Turnstile.
